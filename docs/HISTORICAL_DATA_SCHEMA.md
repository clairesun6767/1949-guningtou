# Historical Data Boundary — V1.1

## Purpose

The V1.1 runtime reads the existing battle package through typed adapters. It does not migrate, rewrite, or promote historical records. The runtime vocabulary is intentionally explicit about evidence so that a renderer cannot turn an approximation into a verified fact.

## Source layers

| Source layer | Current role | Runtime treatment |
| --- | --- | --- |
| `battle.json`, `phases.json`, `events.json` | Canonical package entities | Read through the package adapter; event times become runtime timestamps when valid |
| `locations.geojson` | Six canonical, manually verified Locations | `RuntimePoi`; WGS84 coordinate and coordinate provenance are preserved |
| `routes.geojson` | Canonical route layer | Currently empty; no route is generated by the adapter |
| `units.json` | Canonical unit layer | Currently empty; a unit without source-backed position remains unknown/hidden |
| `evidence.json`, `sources` | Evidence and provenance | Source IDs, evidence IDs, confidence, source confidence, and source metadata survive the boundary |
| `battle-movements.geojson` | Approximate/probable visual interpretation | Remains the existing movement/area presentation layer, not a verified route or unit track |
| `historical-battle-map-traces.geojson` | Schematic source-map transcription | Remains separate from canonical routes; source map identity, labels, registration, and research flags stay intact |

## Runtime evidence vocabulary

```text
confirmed / verified  -> VERIFIED
probable / supported  -> SUPPORTED
estimated / approximate / partial / interpretive -> PARTIAL
disputed              -> DISPUTED
unknown or missing    -> NO_EVIDENCE
```

This is a display/runtime normalization only. It never upgrades the source confidence.

## Route gate

A package route becomes `historicalRouteStatus: verified` only when all three conditions hold:

```text
verificationStatus = source-verified
status             = approved
confidence         = confirmed
```

Every other route is `candidate`, `deprecated`, or `insufficient_evidence` and is marked `researchOnly` as appropriate. Candidate routes cannot leak into visitor production mode.

## Unknowns are first-class

- A missing coordinate is not replaced with a guessed coordinate.
- A missing time remains an untimed record; invalid time is not silently coerced.
- A missing route does not become a straight line between two POIs.
- A missing source/evidence link remains missing and is visible to research tooling.
- Schematic historical-map traces are not treated as precision GIS.

## Data-change boundary

The Phase 1 runtime work changed TypeScript contracts and tests only. No historical JSON, canonical Location, terrain, classification texture, battle movement, or source-trace file was edited.
